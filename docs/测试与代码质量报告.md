## 三、测试设计自评（作业要求回答"这些用例能否满足测试要求"）

**能做到的：**
1. **核心算法全覆盖**：wbi 签名用"按文档手工复算 MD5"做交叉验证，属于最强断言；
   protobuf 解析用手工编码的二进制验证，不依赖真实网络。
2. **边界值明确**：长度 1/100/101、时间 0/359999/360000、样本 10/50 等临界点均有覆盖。
3. **异常路径**：网络重试、重试耗尽、坏 XML、坏 protobuf、空数据集、
   脏搜索结果、清单缺失、统计文件缺失等失败分支都有对应用例。
4. **流水线可测**：用 `monkeypatch` 把输出目录重定向到临时目录，
   验证 clean→analyze→export→visualize→dashboard 全链路的编排与产物。
5. **不需要网络**：全部用例可在离线环境运行，评分方 clone 后 `pytest` 即可验证。

**测试直接发现并修复的真实缺陷：**
- `DanmakuStats.save()` / `export_to_excel()` / `build_dashboard()` / `profile_pipeline()`
  把默认参数写成 `path=config.XXX_FILE`。Python 的默认值在**函数定义时**求值，
  导致运行期修改配置不生效、也无法重定向输出目录。集成测试暴露该问题后统一改为
  `None` 哨兵 + 函数体内取值。

**尚未覆盖的（诚实说明）：**
1. `profile_runner` 是性能分析工具而非业务代码，未写单元测试，覆盖率统计显示 0%；
2. `video_search.search_videos` 的分页轮转逻辑需要接口替身才能测，
   目前只测了 `parse_search_item` 的解析与容错；
3. 未做真实网络请求的集成测试（避免评分环境网络波动导致测试不稳定）；
4. 中文分词的"切词正确性"只能做抽样断言，无法穷举。

**结论**：对"数据处理正确性"这一核心风险，测试是充分的（等价类 + 边界 + 异常三类齐全）；
对"可视化输出美观度"这类主观指标，单元测试本就不适用，改用人工目视检查
（已实际打开 `wordcloud.png`、`top_comments.png`、`profile_chart.png` 确认中文渲染正常）。

## 四、代码质量分析

配置了 flake8 与 pylint（`.flake8` / `.pylintrc`），并遵循项目约定：

```bash
pip install flake8 pylint
flake8 src tests
pylint src/llm_danmaku
```

已落实的规范：
- **命名**：模块/函数 `snake_case`，类 `PascalCase`，常量 `UPPER_CASE`，私有成员前缀 `_`
- **注释**：全部模块、类、公开函数均有中文 docstring（含 Args/Returns/Examples）
- **类型注解**：所有函数签名带类型注解，`from __future__ import annotations` 保证兼容
- **异常处理**：网络请求分类捕获 + 指数退避；单视频/单媒体源失败隔离，不中断整体流程
- **低耦合**：配置集中在 `config.py`；网络访问统一走 `BiliClient`（便于注入替身）；
  统计结果 `DanmakuStats` 作为可视化与导出的唯一数据来源
- **魔法数字**：全部提取为配置常量（关键词、阈值、并发数、字体路径等）
